## A. Issues

### content-model-to-ui: security

- **DL-A1 · high · field-mapping.md:125 vs introspect_schema.py:175-179 — secret columns are shown and editable.**
  - The doc promises `password`, `*_hash`, `api_key`, `*_token`, `secret` become write-only inputs "absent from the read type entirely"; the code matches an exact list only (`password_hash`, `access_token`, `refresh_token`, `api_key`, `secret`…).
  - Repro (`fixtures/saas.sql`, `profiles`): `api_token`, `reset_token`, `webhook_secret`, `token_hash` map to `text-input` on detail + form. Generated `ProfileDetail.tsx` renders all four as plain text (`{record.reset_token}` …) and `ProfileDraft` includes them.
  - Even when the rule fires, "absent from the read type" is only a TypeScript omission: the doc's own queries use `.select('*')`, which sends the column to the browser.
  - Fix: use the documented patterns (`_token`, `_secret`, `_hash`, `_key`), mark matches `never_display`, keep them out of Draft; say secrets must not be selectable by `anon`/`authenticated` (column `REVOKE SELECT`, private schema or Vault); treat a `password*` column in an exposed schema as a schema bug (Supabase Auth owns passwords). Confidence high.
- **DL-A2 · high · introspect_schema.py:1863-1868, field-mapping.md:334, supabase-integration.md:140, scaffold_ui.py:1128 — authorization columns are editable by default.**
  - Same fixture: `profiles.id` (the PK that references `auth.users`, Supabase's canonical profile table) becomes an editable combobox of users; `role`, `is_admin`, `credits`, `org_id`, `projects.owner_id`, `organizations.plan` are editable and all sit in the generated `*Draft` type, which the scaffold calls "the writable columns only" that "stops a form quietly PATCHing a column the database owns". The `readonly_columns` question defaults to just `id`/`created_at`.
  - Under Supabase's standard profile policy (`USING (id = auth.uid())`, no `WITH CHECK`, so `USING` applies), wiring `.update(draft)` lets users raise their own `role`, `is_admin`, `credits`. A TypeScript `Pick` is not access control: RLS is per row, so columns need `REVOKE UPDATE (col)`, `WITH CHECK` or a trigger. The skill mentions none.
  - Fix: default ownership/tenant/role/billing columns to read-only with a `security` signal and their own question (`role`/`*_role`, `is_admin`, `owner_id`, `user_id`, `created_by`, `org_id`/`tenant_id`, `plan`, `credits`, `balance`, `stripe_*`); state that Draft is not a security boundary. Confidence high.
- **DL-A3 · high · supabase-integration.md:99-106, 247; field-mapping.md:311 — the RLS write-failure model is wrong.**
  - (a) "`23503`: often a parent the user cannot see". FK and unique checks bypass RLS ("Referential integrity checks … always bypass row security", [Postgres: row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)), so an invisible parent never raises 23503 — the insert succeeds, which is how a user attaches rows to another tenant's parent. Policies' `WITH CHECK` must confirm the parent is visible/same-tenant; 23503/23505 also leak existence of hidden rows.
  - (b) "A blocked write is loud… returns `42501`". Only INSERT and `WITH CHECK` violations raise it; UPDATE/DELETE on rows `USING` hides change 0 rows and report success (the Postgres page's own `UPDATE 0`). Success does not mean the write happened. Confidence high.
- **DL-A4 · medium · supabase-integration.md:228-244, 194-206 — two samples are buggy.**
  - The optimistic-update `mutationFn` never throws: supabase-js returns `{ error }` unless `.throwOnError()` is used ([throwOnError](https://supabase.com/docs/reference/javascript/using-modifiers-throwonerror)). A 42501/PGRST116 fires no toast and no rollback, and the `onSettled` refetch silently reverts — the "silent rollback" §6 forbids. Fix: `.throwOnError()` and treat a 0-row `.select()` as "not permitted".
  - The keyset sample pastes the cursor raw into `.or()`; Supabase says `filters` "is used as-is… make sure it's properly sanitized" ([or](https://supabase.com/docs/reference/javascript/using-filters-or)). Validate (ISO timestamp, uuid) and quote. Confidence high.
- **DL-A5 · medium · supabase-integration.md:89-90, 162 — unsafe or stale guidance.**
  - (a) `create function can_read_products() … security definer` has no `set search_path = ''` (Supabase advisor lint 0011) and no `revoke execute … from anon`; Supabase says policy-helper security-definer functions "should never be created in a schema in the Exposed schemas" ([RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)).
  - (b) "The JWT's claims" need two caveats: read `app_metadata` only (users can edit `user_metadata`), and claims stay stale until the token refreshes.
  - (c) Realtime DELETE events are not RLS-filtered, and with RLS on `REPLICA IDENTITY FULL` still yields only the PK in `old` ([Realtime troubleshooting](https://supabase.com/docs/guides/troubleshooting/realtime-postgres-changes-troubleshooting)) — the doc's fix fails in the case it targets. Confidence high.
- **DL-A6 · medium · introspect_schema.py:598, 1986-1992; scaffold_ui.py:2068-2076; supabase-integration.md:40; field-mapping.md:342 — the tool cannot see RLS.**
  - The parser skips `ENABLE ROW LEVEL SECURITY` and `CREATE POLICY` and records "RLS policies" as *missing* even when present (the doc says DDL carries them "if the dump includes them"). `app.rls_enabled` defaults to `true`, though `fixtures/saas.sql` leaves `projects` without RLS (readable and writable with the publishable key). Answering "off" only swaps a code comment, though the question says it "changes the generated code".
  - Fix: parse both statements, record per-table RLS/policies, default the answer from the DDL, and block on exposed tables with RLS off, UPDATE policies without `WITH CHECK`, and `using (true)` on writes. Confidence high.

### content-model-to-ui: correctness

- **DL-A7 · medium · introspect_schema.py (`parse_ddl`, :801, :817) — Supabase's own schema outputs are silently misread.**
  - `supabase db pull`/`db dump` is pg_dump `--quote-all-identifier` (supabase/cli `dump_schema.sh`): `"name" "text"` is an unrecognised type, so the title falls back to the uuid PK; `"published_on" "date"` becomes a text input; identity via `ALTER TABLE … ADD GENERATED … AS IDENTITY` is missed, so every `id bigint` is an editable, required number input; schema-qualified enums (`public.product_status`) lose their values.

Repro: `pgdump.sql`, `dbpull2.sql`, `database.types.ts` → `{"subscription_status":["trialing"]}`, 4 of 5 columns. Confidence high (formats checked against the CLI source and a real generated file).
- **DL-A8 · medium · scaffold_ui.py:1269-1278, 1327-1337; SKILL.md:74 — interview answers are ignored.**

  - `cardinality`, `label_column` and `default_sort` answers are never read either (only 8 answer kinds, scaffold_ui.py:165-200). Fix: thread currency/scale into cells, or mark which answers are advisory. Confidence high.
- **DL-A9 · medium · scaffold_ui.py:436, 445, 456, 1773, 1949 — generated forms lack promised a11y wiring** (screen-patterns.md:304; `Field`'s docstring).
  - No control gets `aria-describedby`: ids go to a `data-describedby` on a wrapper div, which assistive tech ignores, so help and error text are unlinked. `RadioGroup` gets `labelledBy="<id>-label"` but the label has no id (unnamed group).   - Fix: put `aria-describedby`/`aria-invalid` on the control; id the label or use `<fieldset><legend>`; drop `role="alert"` from inline errors; focus the summary. Confidence high (from generated code; tsc is clean, so it won't catch this).
