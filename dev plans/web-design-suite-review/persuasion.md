# web-design-suite 3.0.1 review — persuasion group (PS)

**Scope:** landing-page-conversion, client-presentation-builder and design-critique-gate. Reviewed 2026-09-23; no plugin file was changed.

**How repros were run:** on copies in the session scratchpad, with `PYTHONDONTWRITEBYTECODE=1` set and `PYTHONPATH` pointing at the skill copy. The fixtures are saved in `persuasion-fixtures/` beside this file. Paths are relative to `skills/`. Nothing here repeats the bug-fix report's "Fixed" or "Judged not to be bugs" tables.

## A. Issues

**PS-A1 · high · The deck asserts claims that its own inputs contradict.** **Where:** `client-presentation-builder/scripts/build_presentation.py:952-958, 868, 915-919, 838, 973-976` **What's wrong:** The accessibility slide's "Say it this way" callout always reads "this page passes an automated WCAG 2.2 AA check and has been keyboard-tested by hand". It says this even when `a11y.json` has violations, and although no input records any keyboard test. The performance slide is always titled "It is fast, and it stays fast". It also advises raising open errors only "if anyone is technical". The creative-director slides claim "Nine laws, machine-enforced", but audit_design checks only L1–L6 (see the README section "What the gate actually catches"). The same slides say every colour pair "clears its floor by measurement", with no contrast input behind it. This breaks SKILL.md:211-215 ("It invents nothing") and evidence.md §1, §3 and §4. **Repro:** Run `python -m scripts.build_presentation DECISION_LOG.md --audience client --a11y a11y.json --defence defence.md -o deck.html`, where defence.md comes from `critique_report findings-control.json --format defence`. Slide 5 reads: "2 automated violations … critical 1 serious 2 … Say it this way: The honest claim: this page passes an automated WCAG 2.2 AA check and has been keyboard-tested by hand." Add `--perf perf.json` (912 KB against a 600 KB budget, 1 error). The slide reads: "It is fast, and it stays fast … 152% of budget used … Raise these yourself if anyone is technical." **Fix:** Choose the wording from the data, and add a gap when the page is over budget. Claim keyboard testing only when an input records it, for example a `## Tested by hand` section. Say "L1–L6". Add a test for each case.

**PS-A2 · high · The defence sheet presents suspicions as known flaws and drops confirmed defects.** **Where:** `design-critique-gate/scripts/critique_report.py:678, 691`; `assets/CRITIQUE_TEMPLATE.md:125-150` **What's wrong:** "Known flaws you are carrying in" keeps only findings that are *not* confirmed, or that set `defend: true`. The empty-state line reads "Every finding is either fixed, confirmed, or taste", treating confirmed as if it meant fixed. The schema has no fixed state, and the template has no `defend` field. build_presentation copies this table onto the client's "What we are not happy with yet" slide. That inverts SKILL.md:215 and narrative-structure §8. **Repro:** `critique_report findings-control.json --format defence` lists only "Icon weights may differ | minor | Suspicion only.". The confirmed major finding "Muted text on the sunken band fails contrast (Measured 3.2:1)" appears nowhere. The A1 deck shows the same single row. **Fix:** Add `status: open|fixed`. Carry every open finding that is neither taste nor blocking, and label suspicions as suspicions. Add `status` and `defend` to the template.

**PS-A3 · high · The audit merge silently deletes whole rule groups.** **Where:** `critique_report.py:474` (`if rule and rule in hand_text`) **What's wrong:** A hand finding that merely contains a rule's name as a plain English word folds that rule's entire machine group. The L5 rule is literally named `important`. The fold is silent in `triage`, `defence` and `--summary`, which never print merge notes. It defeats `--audit-blocking` and contradicts SKILL.md:278-280 ("not silently deleted"). **Repro:** audit.json holds three `important` findings; the hand finding is titled "The most important plan is not visually recommended". `critique_report findings.json --audit audit.json --format triage` prints no `important × 3` line. A control title without the word prints `[MAJOR] [conformance] important × 3`. `… --audit-blocking important --fail-on blocking --summary` exits **0**. The control prints `1. [blocking] important × 3` and exits **1**. **Fix:** Fold only on an explicit `covers:` field, or a backticked rule id matched on word boundaries. Never fold escalated rules. Print merge notes to stderr in every format.

**PS-A4 · high · The design gate passes HTML without auditing it.** **Where:** `landing-page-conversion/references/worked-example.md:377` and `SKILL.md:221-227`; root cause in `web-design-studio/scripts/audit_design.py:1021-1032` **What's wrong:** Given a directory, the gate walks only CSS and JS files. Given an `.html` file directly, it hands it to the JS auditor, which ignores `<style>` and `style=""`. Either way it reports "clean — all nine laws hold". The worked example's "extracted HTML | clean" row therefore checked nothing. **Repro:** `bad-page.html` contains `<style>.hero{margin-top:37px;color:#ff0000;font-size:13px !important}#buy{padding:7px}</style>` and `style="margin:13px;color:#f00"`. `python -m scripts.audit_design <folder> --strict` prints "design audit: clean — all nine laws hold." and exits 0. Passing the file directly gives the same result. **Fix:** Audit `<style>` and `style=""` in `.html`, `.vue`, `.svelte` and `.astro` files. Fail with "0 files audited" when nothing matched. Until then, have Phase 6 name the CSS files it audits and state the limitation.

**PS-A8 · medium · The skills give opposite instructions for a risky client request.** **Where:** `client-presentation-builder/references/evidence.md:280-285`; `objection-handling.md:236` vs `:259-264`; `landing-page-conversion/SKILL.md:260-281` **What's wrong:** evidence.md §7.3 says, of "something that creates a legal exposure": note the risk, then "build it. So when a client asks in a review for a resetting countdown or a pre-ticked upsell, Claude gets opposite answers depending on which skill is loaded. **Fix:** adopt one shared policy — recommend against accessibility risks in writing, decline deceptive or unlawful patterns, and refer legal questions to a specialist.

For an ordinary company page, it adds nothing to the UCPD. **Digital Fairness Act.** The skill calls it "proposed". ## B. Gaps

**PS-B1 · Accessibility of persuasive patterns.** The skill prescribes sticky bars, deadlines, carousels, modals, consent banners, and multi-step signup and password forms. It never maps them to the WCAG 2.2 criteria they touch ([W3C](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)): 2.2.1 Timing Adjustable and 2.2.2 Pause, Stop, Hide; 2.4.11 Focus Not Obscured (sticky bars); 2.5.8 Target Size (24px at AA — the suite's 44px is policy, not the requirement); 3.3.7 Redundant Entry and 3.3.8 Accessible Authentication (signup); 4.1.3 Status Messages (toasts). Critique layer 8 doesn't check them either. **Suggested scope:** a table in conversion-audit §7, a matching critique probe, and a pointer to a11y-audit-runner.

**PS-B2 · Consumer law beyond the EU/US basics.** The author is a UK company, and none of this is covered: **UK:** the DMCC Act has been in force since 6 April 2025. It bans fake reviews and drip pricing, with CMA fines of up to 10% of turnover ([CMS](https://cms.law/en/gbr/legal-updates/the-dmcc-act-consumer-elements-come-into-force-from-6-april-2025)). Its subscription rules are now expected in spring 2027 ([Taylor Wessing](https://www.taylorwessing.com/en/insights-and-events/insights/2026/04/subscription-contracts)). **EU reviews:** UCPD Annex I 23b/23c and Art 7(6) on verified reviews. **EU pricing:** Price Indication Directive Art 6a (a "was" price must be the lowest of the prior 30 days), and CRD Art 6(1)(ea) (personalised-price disclosure). **EU withdrawal:** CRD Art 11a requires a withdrawal button from 19 June 2026 ([2023/2673](https://eur-lex.europa.eu/eli/dir/2023/2673/oj/eng)). **Consumer pricing:** B2C prices must include VAT. **Drip pricing** is missing from the ethics table, although "extra costs" is Baymard's top abandonment reason (40%). **Suggested scope:** a dated "flag for legal review" table, not legal advice.

**PS-B3 · Price experiments.** conversion-audit §9 treats every A/B test alike. Price tests raise EU disclosure duties (6(1)(ea)), the obligation to honour the lowest price shown, and the risk of backlash when customers discover them. Revenue per visitor is also far noisier than conversion rate. **Suggested scope:** favour testing packaging over price discrimination.

**PS-B4 · Page types and audiences.** Every example is audio, AI or agency (copy-patterns.md:5). There are no sequences for: B2B "book a demo" pages for a buying committee (security review, ROI); gated lead magnets; local booking and donation pages; regulated claims (health, finance, UK financial promotions); localisation (transcreation, currency and tax, text expansion); PPC message match.

**PS-B5 · Checks Claude can't honestly run.** Five-second tests with five people, squinting, "on an actual phone" and "leave it overnight" all need a human. No tool produces the blurred, greyscale, mirrored, 25% or 390/1440 screenshots that Claude could inspect instead. CRITIQUE_TEMPLATE offers only yes/no; it needs a "not run — needs a human" state.

**PS-B6 · No claims layer, and siblings don't route to each other.** The critique gate has no honesty or claims layer: a fake countdown, a pre-ticked opt-in or an unsourced "47% faster" passes all ten layers. landing-page-conversion never routes to perf-budget-gate or a11y-audit-runner, although its description promises an LCP/CLS audit. design-critique-gate never names a11y-audit-runner or component-state-matrix, even though its layers 6–8 redo their work by hand. Nor does it name client-presentation-builder, which consumes its defence sheet.

**PS-B7 · Presenting in practice.** **Remote:** pressing N while screen-sharing shows the client the notes and "Gaps — fix before you present". There is no presenter window. **Missing playbooks:** nothing covers a client who rejects the whole direction, or an absent decision-maker (for example, a recorded walkthrough). **Iteration reviews:** DECISION_LOG can't express "what you asked last time" or "what we did not change" (§3.2).

**PS-B8 · Consent for tracking.** conversion-audit §8–9 recommends session recordings, heatmaps and last-field form analytics with no mention of consent (GDPR, ePrivacy, PECR) or masking of personal data. Consent banners are themselves a dark-pattern hotspot.

## C. Improvements

**PS-C1 · Make the deck honest by construction (M · P1).** Choose wording from the data. Take manual-test evidence as an input. Add a `--handout` print mode. Add a presenter window synced over BroadcastChannel, so notes never appear on a shared screen. Accept both suite a11y shapes, and exclude reversed decisions. Add tests. **Why:** it is the skill's core promise, and it fixes A1, A5–A7, A21 and B7.

**PS-C2 · Fix critique_report (S · P1).** Add an explicit `covers` field for merges. Print merge notes in every format and on stderr. Add a `status` field, and count open defects as carried flaws. Update the template, and add tests from the fixtures. **Why:** fixes A2 and A3.

**PS-C3 · Close the HTML blind spot, with web-design-studio (S–M · P1).** Audit `<style>` and `style=""`, and fail when zero files were audited. Fixes A4.

**PS-C4 · Add an adversarial critic subagent, `agents/design-critic.md` (S–M · P1).** Give it `tools: Read, Grep, Glob, Bash`, `skills: [design-critique-gate]` and `omitClaudeMd: true`. It critiques the page in a fresh context and returns a `findings.json` the main thread does not edit. **Why:** Claude critiquing its own build in the same context is exactly the familiarity blindness the skill describes.

**PS-C5 · Add `critique_snapshots.mjs` (M · P2).** A Playwright script that reuses a11y-runner's browser discovery. It renders PNGs at 390 and 1440px, plus blur, greyscale, mirror, 25%, dark and reduced-motion variants, and a contrast table from computed styles. **Why:** it makes the B5 checks runnable.

**PS-C6 · Add `lint_claims.py` (M · P2).** It flags: countdowns computed from load time; "only N left" and "N people viewing"; pre-`checked` opt-ins; `autocomplete="off"` on personal fields; a lazy-loaded first image; two filled CTAs, or mismatched CTA labels; struck-through prices; unsourced percentages. Run it in landing Phase 6 and critique layers 1 and 8. Optionally add a non-blocking PostToolUse hook on HTML writes that returns `additionalContext`.

**PS-C7 · Add an eval suite in `evals/`, scored against a no-plugin baseline (M · P2).** Cases: A resetting countdown is refused. Testimonials are not fabricated. A deck built from 3 critical axe violations never says "passes" (regex check). A critique names mechanisms, labels taste, and gives a top three. "Does the DSA apply to my Shopify store?" is scoped correctly. Routing: "make this convert better" goes to landing, "does this look professional" goes to critique, and "deck for tomorrow's review" goes to presentation, not pptx. This needs Claude Code 2.1.269 or later. The `claude.exe` on PATH is 2.1.160 and has no `plugin eval`. Cases that run scripts need WSL2.

**PS-C8 · Put landing-page-conversion on a token diet (S–M · P1).** At about 6.6k tokens, it is the largest skill in the suite (the other two are about 4.6k and 4.3k). Target 4k or less: Move the Phase 5 table and markup, the legal detail and the sources into references. Keep one copy of the NN/g figures instead of three. Put ethics and evidence first (A11).

**PS-C9 · Rewrite the descriptions (S · P2).** All three run 937–955 characters. Lead with the use case, and add "not for" lines that separate: landing from critique on "audit this page"; critique from the installed `design:design-critique`; the deck from pptx.

**PS-C10 · Add an evidence register, `references/sources.md` (S–M · P2).** Record each figure's value, URL, date verified and exact quote. Add a test that every number in the docs appears there. Use placeholders in example lines. **Why:** numbers drift. Baymard's 11.3 is a 2024 figure, while its abandonment page still says 14.88.

**PS-C11 · Add a user-invocable chain skill (S · P3).** Set `disable-model-invocation: true`. It runs audit → critique → defence → deck, and stops on blockers.

**PS-C12 · Bridge MESSAGE_BRIEF to DECISION_LOG (S · P3).** Positioning choices become decisions, and assumptions become open questions.
