# Pro Web Design Suite: the full audit of `main` at `8441ff0` (2026-10-28)

**What this is.** A complete audit of the plugin as it stands on `main` after 4.0.1 and the six fixes queued for 4.0.2: every script, every browser script, the hooks, the MCP server, the shipped lint configs, the test suite, CI and release, the evals, the distribution repository, every shipped document, and the planning documents. It records **281 findings** (4 critical, 44 high, 109 medium, 124 low) and **23 items of work still open**, and it feeds the runbook beside it, [`web-design-suite-completion-runbook.md`](web-design-suite-completion-runbook.md), which schedules all of it.

**The detail is in the folder [`web-design-suite-audit-2026-10-28/`](web-design-suite-audit-2026-10-28/):** thirteen files, one per pass, each finding with its file and line, its evidence (a command and its output where it was reproduced), its effect, its fix and a confidence. This file is the summary, the ranking and the reading of the whole. Finding ids are the pass's prefix and a number (`PY-A-1`, `JS-B-1`, `DOC-B-3`, `OPS-1`, `TEST-4`, `PLAN-2`); the index at the end lists every one.

## 1. The verdict in one page

- **The plugin is close to done, and not done.** By the execution plan's own seven criteria (§1 there) three fail today: `main`'s CI is red (the macOS 3.14 leg of the docs merge failed in a timing test the handoff lists as a Windows flake), the owner's install is still 3.6.0, and `main` carries six unreleased fixes. Everything else in the definition holds: every review item is closed, the three gates come from one spec, the plugin has its hook, commands, agents and MCP server, the evals passed on 4.0.1, and the release pipeline is clean byte for byte.
- **The code has real defects the suite did not catch.** Four are critical: three scripts can silently overwrite or corrupt a user's own files, and the schema reader drops any column whose name begins with `check`, `unique` or `exclude`. Forty-four are high: a class of theme-selector misreadings that makes three readers (the shared token reader, the docs extractor and the diff) take a dark theme's values for the defaults; a runtime gate that hangs forever on a page whose font never loads (this is the owner's unexplained 390 px hang, now reproduced); gates that fail correct code (the standard `:focus:not(:focus-visible)` idiom, a commented-out line in SCSS, field names such as `units`, a confetti animation) and pass wrong code (text faded by `opacity`, an iframe's focusable child); and a shipped stylelint config whose component rules never reach component files at the placement the references name.
- **Most findings are drift, not design.** Of the 281, 87 are bugs, 24 gaps and 9 risks in code; 81 are contradictions, stale facts and undocumented flags in the shipped documents; 19 are stale or contradictory statements in the plans; the rest are test, CI and tooling gaps. The architecture (one rule spec, the token contract, the gates as the enforcement, the evals as the proof) is sound and was found sound by every pass. What drifted is the detail around it: a guard list not extended when a fourth output was added, a regex without a word boundary, a reference that kept an old figure after the ramp changed, a plan that still says 3.2.1 is the latest release.
- **The process has two holes that let the above reach `main` and a release.** Nothing is required to merge (no branch protection, no ruleset), CI cancels `main`'s own runs when the next merge lands, and a `v*` tag releases and distributes without checking that CI passed on the tagged commit. The local runner selects tests by file-name substring and skips whole areas (four agents, two command scripts, most reference edits), and the fail-before tool counts an error as a failure, so "fails before, passes after" can be true for the wrong reason.
- **Nothing was found that leaks data or writes outside the project**, except the MCP server's project guard, which a Windows drive-relative path (`C:..\outside.css`) fools, and a CrUX API key sent in a query string (documented and refused on the command line, but logged by proxies).

What to do first is in the runbook. In one line: make `main` green and gate it, fix the four criticals and the theme-context class, bound the browser scripts' waits, then the rest by file cluster, each with a test seen failing on `v4.0.1`.

## 3. The critical findings

Each can cost a user their own file or silently misread their data. All four are confirmed by a run, all four are small to fix, and all four need a regression test seen failing on `v4.0.1`.

### PY-B-1 · `cluster_values.py` overwrites the project's own DTCG token file
`skills/design-token-migration/scripts/cluster_values.py:2858, :2974`. The overwrite guard names `tokens.css`, `mapping.json` and `reconciliation.md`; the script also writes `tokens.json` (added with P31) and never checks it. `--tokens tokens.json -o <that folder>` replaces the input with the proposal. **Fix:** add `tokens.json` to the guarded names; test that the command exits 2 and leaves the file byte-identical.

### PY-E-1 · `build_email.py --text` is never passed to the overwrite guard
`skills/email-template-system/scripts/build_email.py:1392, :1438-1441`. `--out` is guarded; `--text` is not, so `--text emails/receipt.html` writes the plain-text part over the source template and exits 0. **Fix:** guard `--text` against the source, the token file and `--out`, and `--out` against `--text`; test it.

### PY-A-1 · The DDL reader drops columns named `check…`, `unique…`, `exclude…`
`skills/content-model-to-ui/scripts/introspect_schema.py:1142`. A `CREATE TABLE` item is classed as a table constraint by `startswith(("primary key", "foreign key", "unique", "check", "exclude", "not null "))`; three keywords have no boundary, so `check_in`, `checksum`, `unique_code`, `exclude_from_search` vanish from the model with no warning, and the scaffold ships screens without them. **Fix:** match the keyword with a word boundary; test with those eight columns.

### PY-C-1 · Both the docs extractor and the diff file a theme-scoped re-point as the theme's own override
`skills/design-system-docs/scripts/extract_system.py:1061-1065`, and the same in `diff_system.py`. `[data-theme="dark"] .inverse { --fg-default: var(--neutral-900) }` is read as the dark theme's `--fg-default`, and because the last override wins, the starter's own dark theme resolves its text to neutral-900 on a neutral-1000 canvas: the generated docs measure the starter's dark text at 1.14:1 and the diff reports the wrong dark values. **Fix:** treat a selector as a theme context only when the `[data-theme=…]` compound is the whole selector (optionally after `:root`/`html`); anything with a combinator after it is scoped. One regex in each script; a test with the starter.

The fourth is one of a family. **PY-A-7** (high) is the same misreading in `shared/project_config.py:428-429, :537-540`, the reader every gate uses: `html.dark`, `:root.dark`, `html[data-bs-theme="dark"]` and `html[data-mode="dark"]` pass as default rules, and "last wins" makes the dark theme's values the contract's defaults for every gate. **PY-C-4** (high) is its mirror image: `:root:not([data-theme="light"])` inside `@media (prefers-color-scheme: dark)`, the usual "follow the OS unless overridden" idiom, is classified as a *light* theme. Together they are one defect, "which rule is a default and which is a theme", in three readers that each wrote their own answer. The runbook fixes them as one PR with one shared rule.

## 4. The high findings, by theme

Forty-four findings. Grouped by what they have in common, since the groups are the work packages.

### 4.1 A gate that never returns (the 390 px hang, reproduced)
- **JS-B-1** `a11y_runtime.mjs:3024` awaits `document.fonts.ready` inside `page.evaluate`, which has no timeout. A font request outstanding at that moment that never completes leaves the promise pending forever: the run prints `browser:` and nothing else. The same unbounded wait is in `critique_snapshots.mjs:334` and `snapshot_matrix.mjs:429`. This matches the owner's symptom on webawesome.com's home page at 390x844 exactly, and the live check's follow-up L8 is answered by it.
- **JS-B-2** `a11y_runtime.mjs:1180, :1195`: on the same page every focus screenshot waits 30 s for fonts, twice per stop, the errors are swallowed into `entry.error`, and the check reports no focus findings at all.
- With them, medium **JS-B-8**: `browser_common.mjs:748-752` spawns each page or viewport child with no time limit and captures its stderr, so one hung child hangs the whole run with nothing on screen. The structural fix is one bounded-wait helper around every page-controlled promise, a timeout on each screenshot, a per-child timeout, and a log line *before* each step starts.

### 4.2 Wrong answers from the runtime accessibility gate
- **JS-B-3** a same-origin iframe with a focusable child is reported as an `unreachable-control` error (the stop is recorded as the inner element, never the frame's own path).
- **JS-B-4** the contrast walk reads only `backgroundImage` and `backgroundColor`, never `opacity`, so text faded by an ancestor at `opacity: 0.3` passes at its declared colour.
- **JS-B-5** "visible text" for the label-in-name check is `textContent`, which includes `aria-hidden` icon text and visually hidden spans, so an accessible button is a false `label-not-in-name` error.

### 4.3 The static gates fail correct code and pass wrong code
- **PY-D-1** `a11y_static.py:1734` blanks `/* */` comments only, so in `.scss`, `.less` and `.pcss` a commented-out `// outline: none;` is read as live and fails the commit.
- **PY-D-2** `a11y_static.py:1746-1770` looks for a focus replacement in the same rule only, so the standard `:focus:not(:focus-visible) { outline: none }` idiom (MDN's recommendation) is an error.
- **PY-D-3** `a11y_static.py:310-322` searches the personal-field hints as unanchored substrings, so `units`, `community`, `opportunity_id` and `downtown` demand `autocomplete="address-line2"`.
- **PY-D-27** `lint_claims.py:71, :321-324` raises the error `invented-scarcity` whenever `Math.random` sits within three lines of the word `left`, which every particle and confetti animation sets as a CSS property.
- **PY-B-4** `audit_design.py:318-322, :671-676, :1281` exempts pseudo-class-only selectors from the depth count at the top level too, so a stylesheet whose top-level rules are `:root`, `:where(body)` or `:is(…)` is never reported as unlayered, and nesting beneath such a rule is under-counted by one.
- **PY-B-5** `extract_literals.py:1001, :464-501` finds declarations in the comment-blanked text but reads the value back from the real text, so a comment between slots reaches the census and the codemod.

### 4.4 The migration and the versioning tools mis-map or mis-write
- **PY-B-2** `apply_codemod.py:740-742` replaces the span from the duration to the last easing *after* it, so `transition: opacity ease 200ms` becomes `opacity ease var(--motion-hover)`, two timing functions, a transition the browser drops.

- **PY-C-5** `diff_system.py:2447-2448` writes every migration-guide item as `apply_codemod … --kind color` (nothing sets `kind_hint`), which `apply_codemod` refuses for a spacing rename.
- **PY-C-6** `deprecate.py:836` keys consumers by the folder's basename, so two roots named `src` keep only the last and the ledger's evidence undercounts.
- **PY-C-7** `deprecate.py:680-686` `add --mapping FILE` writes over a `--source` file with no overwrite check.
- **PY-C-8** `figma_to_tokens.py:426-430` writes a line-height FLOAT unitless (`24` becomes a 24× multiplier) while the audit reads the same `24` as a percentage.

## 7. The systemic causes

Eleven classes explain most of the 281. The runbook attacks the class, not the instance, so each fix carries a test for the class.

1. **A guard list not extended with the thing it guards** (PY-B-1, PY-E-1, PY-C-7, PY-C-18): `refuse_overwrite` is called with a hand-written list of outputs; a fourth output or a second flag was added without it. *Class fix:* one helper per script that collects every path the script writes and every path it reads, called once.
2. **"Which rule is a default and which is a theme" answered three times** (PY-A-7, PY-C-1, PY-C-4, PY-B-7): three readers each wrote a selector classifier. *Class fix:* one function in `shared/project_config.py`, used by all, with the idioms as fixtures.
3. **Substring matching where a token was meant** (PY-A-1, PY-A-3, PY-D-3, PY-D-6, PY-D-8, PY-D-27, PY-D-28, JS-A-3, DOC-A-1's test): `startswith`, `in` and unanchored `re.search` on words. *Class fix:* word boundaries, and the test that pins the near-miss.
4. **Reading the real text after scanning the blanked text** (PY-B-5, PY-D-1): comments blanked for the scan, then values read from the original. *Class fix:* read from the blanked copy, and blank `//` for the Sass family.
5. **Page-controlled promises awaited without a bound** (JS-B-1, JS-B-2, JS-B-8, JS-B-23): `document.fonts.ready`, screenshots, a child process. *Class fix:* a `bounded()` helper and a per-child timeout; a log line before each step.
6. **A number read as something it might be** (PY-C-2, PY-C-20, PY-C-8, PY-A-12): a bare `600` as hex, `50%` as 50 ms, a FLOAT as a multiplier, three references as a shadow. *Class fix:* require the marker (`#`, a unit, a scope) before the type.
7. **A rule enforced in one gate and stated differently in prose** (DOC-B-2, DOC-B-3, DOC-B-19, DOC-A-13, JS-A-2's placement): the spec is `design-rules.json`; the prose restates it by hand. *Class fix:* every prose statement of a rule either quotes the generated block or is pinned by a test against the spec (the sync already does this for the lint configs' data blocks; extend it to the Law 5 list and the focus rule).
8. **Figures that moved after they were quoted** (DOC-B-5, DOC-B-6, DOC-B-18, DOC-B-23, DOC-B-29, DOC-A-21, DOC-B-37): a ramp step, a ratio, a survey figure. *Class fix:* every number in a reference is either computed by a test from the starter (as `test_numbers` does for some) or registered in `evidence.json`; no third kind.
9. **A help text or a flag table that drifted from the parser** (DOC-B-1, DOC-B-20, DOC-A-9, DOC-A-10, DOC-A-24, PY-B-26, DOC-B-38, DOC-C-11): the flag test checks names, not values or defaults. *Class fix:* extend `test_docs.DocumentedFlags` to values of `choices` and to every flag in `--help` having a documented home.
10. **Selection by substring in the maintainer tools** (TEST-2, TEST-3, PY-E-9): `check.py` picks test modules by file-name substring. *Class fix:* a folder-to-module map, and a test that every shipped file maps to at least one module.
11. **No gate on `main` or on a tag** (OPS-1, OPS-2, OPS-4, TEST-1, TEST-4): the rules say "merge on CI green"; nothing enforces it, a tag does not check it, skips are silent, and the fail-before evidence can be an error. *Class fix:* a ruleset, a CI check in `release.yml`, a required-browser flag on every leg, and a fail-before table that separates errors from failures.

Beyond these: **the plans are written to but not read back** (PLAN-1 to PLAN-19). Three documents each hold a "where things stand" that was true once (the completion plan's, the distribution plan's, `dev plans/README.md`'s). *Class fix:* one state, in `docs/HANDOFF.md` and `CLAUDE.md`'s Current state; every other document gets a dated status line pointing there, never its own copy.
